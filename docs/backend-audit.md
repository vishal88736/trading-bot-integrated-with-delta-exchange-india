# Backend audit

Reviewed on 2026-11-08. Scope: engine lifecycle, execution mode, credential/account separation, persisted state, order/fill parsing, native stops, indicators, historical replay, HTTP controls, reference workers, and local runtime health.

## Account display finding

Paper mode simulates trades locally. Connecting a demo key enables separate authenticated account reads; it does not convert existing simulations into exchange positions or change the execution mode. Account positions must come exclusively from Delta's account API.

The API now identifies the active execution mode, order destination, position origin, and state file explicitly. Simulated trades appear in **Automation → Paper simulation**. **Account → Demo exchange positions** displays exchange rows and their freshness. The header always identifies the trading mode independently of account connectivity.

## Confirmed defects and changes

| Area                     | Reproduced issue                                                                                                                                      | Change and validation                                                                                                                                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stop precision           | TP1 could set a local/replay stop to an entry such as `100.03` when the contract tick was `0.1`, while the exchange request rounded it to `100.0`.    | Shared stop progression rounds to the product tick. Runner, replay, restart, and independent broker scenarios cover fractional entries.                                                                                                                  |
| Fill confirmation        | Integer conversion could truncate fractional size/unfilled data; a missing paid fee became zero. Receipt identity was not checked.                    | Require whole contract quantities, a completed fill, the requested product/side/client order ID/reduce-only flag, and a finite paid commission. Unconfirmed responses retain pending recovery state.                                                     |
| Native protection        | A non-finite stop price or explicitly incorrect side could pass the account check.                                                                    | Validate finite positive price and available protection metadata. Stop edits confirm the acknowledged order ID and price without repeating the write. Position-wide brackets follow Delta's full-position semantics rather than standalone order sizing. |
| Leverage acknowledgement | Successful HTTP status alone was treated as confirmation of the requested leverage.                                                                   | Verify the reported leverage and product; an inconsistent acknowledgement preserves recovery state and blocks entry.                                                                                                                                     |
| Startup/status           | Client initialization happened outside the worker error handler. Status could read changed file settings while the worker used its captured settings. | Capture initialization errors, report active execution settings, expose configuration drift, and serialize atomically persisted state rather than a partially mutated worker object.                                                                     |
| Credential isolation     | Credential edits relied on the saved mode instead of the active mode. Malformed credential files could break status.                                  | Use active settings for credential guards; report a recoverable credential error without exposing contents. Paper clients receive no exchange credentials.                                                                                               |
| Recovery integrity       | Persisted position structures lacked validation; reconciliation truncated account size data.                                                          | Validate position quantities, targets, stages, and finite state values. Reject malformed account quantities before clearing a recovery record.                                                                                                           |
| CMO precision            | After mixed price scales, subtractive rolling sums could leave a flat window at `+100` or `-100` rather than zero.                                    | Accurately sum the bounded gains/losses window with `math.fsum`; regression cases cover flat tails after large changes.                                                                                                                                  |
| Start intent             | Demo confirmation existed only in the UI.                                                                                                             | The backend requires explicit demo confirmation and can check the expected mode before creating the worker. The existing UI confirmation supplies these fields.                                                                                          |

Regression tests were added for the original failing cases before their fixes. Fault-injection tests continue to check incorrect stop moves and partial allocations. Backtrader independently executes 20 controlled broker scenarios, including fractional-entry stop rounding.

## Checks and boundaries

- All account probes performed during the audit were read-only. No exchange orders, leverage changes, cancellations, or stop amendments were sent by the audit.
- The selected-product position endpoint and the all-account position snapshot were checked independently. Private diagnostics stay under ignored `.runtime/evidence/`; no keys, account IDs, or balances are published here.
- Public and demo history, complete range validation, candle-close/next-open timing, higher-timeframe availability, fees, gaps, final settlement, and the SL ladder are covered by replay tests and historical probes.
- The local server's current health, stored state signatures, recovery flags, and recent log errors were inspected. Historical startup markers are not treated as current failures.
- Python tests, UI DOM tests, package checks, and CI are separate evidence from live exchange execution. Actual demo order fills, asynchronous settlement behavior, native stop amendments, and external/native-stop reconciliation still need a dedicated live demo validation run.
- Unconfirmed or incomplete writes remain paused for account reconciliation; the bot does not retry exchange writes automatically.
- Backtrader's scenarios test controlled order paths, not an independent replay of all historical indicator signals. Funding, taxes, liquidation, liquidity, and full intrabar order are outside the simulator's model.

API contracts were checked against [Delta's API documentation](https://docs.delta.exchange/), including [position-wide brackets](https://docs.delta.exchange/#place-bracket-order). The source and pinned reference revisions are listed in the [README](../README.md).
